# Independent reference calendars

`OpenHolidaysReferenceTest` compares provider output with downloaded OpenHolidays
API records, without network access during PHPUnit runs. The expected dates are
never generated by `HolidayCalculator` or `tests/regenerateTests.sh`.

Saved calendars cover all 36 countries listed by the API's
[`/Countries`](https://openholidaysapi.org/Countries?languageIsoCode=EN) endpoint
at retrieval time, for 2020–2025, with English holiday names.
The country list in `sources.json` is a snapshot; updates download the listed
countries without automatically discovering new ones. Responses are preserved in
full, including bank and optional holidays and regional or multi-day records.

Provider comparison coverage remains PL, DE, DE-BE, CZ and AT for 2024 and 2025. This includes movable
holidays, Poland's Christmas Eve introduced in 2025, and Berlin's one-off
Liberation Day in 2025. This is modern calendar coverage, not historical validation.

Run with:

```sh
php vendor/bin/phpunit tests/Reference/OpenHoliday
```

## Data provenance and license

The JSON files in `Data/` concatenate OpenHolidays API responses in chronological
request order, reformatted with indentation only. Each country uses three
two-year requests (2020–2021, 2022–2023 and 2024–2025) to stay within the
API limit of three years per request. OpenHolidays API is published by STÜBER SYSTEMS GmbH.
These data files are distributed under the
[Open Database License 1.0](https://opendatacommons.org/licenses/odbl/1-0/),
separately from the package's code license. See the publisher's
[license statement](https://www.openholidaysapi.org/en/faq/) and
[underlying sources by country](https://www.openholidaysapi.org/en/sources-europe/).
`sources.json` records request URLs (`urls` for each country), retrieval time,
coverage and hashes of the combined files.

`names.json` maps external English names to this library's identifiers. Mapping
does not derive dates from provider output. New unmapped reference names fail the
test, and empty reference coverage fails instead of silently passing.

## Comparison scope

The test compares sorted lists of `date + holiday identifier`, preserving
duplicates. It checks national full-day public holidays and, for Berlin, national
holidays plus records explicitly applicable to DE-BE. Regional holidays are not
treated as national holidays. Multi-day or partial-day reference records fail
explicitly and require a deliberate extension of the test.

Provider output includes DAY_OFF holidays except PARTIAL_ONLY entries. The test
does not validate every classification bit, observances, school calendars,
translations or compensatory-day rules. Two explicit adaptations apply to Poland:

- Christmas Day and Second Christmas Day are included by identifier because the
  existing provider omits DAY_OFF on them. Their dates and existence are tested;
  the missing classification remains a known provider issue.
- Armed Forces Day is excluded as an additional commemoration on Assumption Day;
  OpenHolidays represents that public holiday with a single Assumption record.

Other extra full-day DAY_OFF holidays fail comparison, as do missing holidays,
wrong dates, wrong identifiers and duplicate entries.

## Updating and extending

Run the registered console command from the project root (PHP with HTTPS stream
support and `allow_url_fopen` enabled is required):

```sh
php tests/console test:reference:openholidays:update
```

To update and test without a local PHP installation, follow the
[Docker instructions in the main README](../../../README.md#reference-data-with-docker).

`php tests/console test:reference:update` updates OpenHolidays, GOV.UK and Azure (Azure updates require Python/PyArrow).
The source-specific command above updates only OpenHolidays.

The command downloads all URLs in `sources.json`, validates non-empty JSON holiday
lists and combines each country’s responses, and only starts replacing files after every download has succeeded.
Individual files are replaced through temporary files in the same directory.
It updates `retrievedAt` and SHA-256 hashes of the formatted files, preserving
coverage, source URLs and license metadata. Name mappings are never regenerated.
A network error or invalid response aborts before any reference files are changed.

Review the resulting diff against the publisher's underlying sources and run the
reference tests before committing. Changed snapshots are not automatically
approved; reference dates are never calculated from provider output.

To add a country or region, save its response and provenance, add explicit name
mapping, and add named cases to `provideCalendars()`. Check the semantics of local
public holidays first. A discrepancy is a reason to investigate both sources,
not proof that either the provider or the external API is correct.
